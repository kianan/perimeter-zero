# Brief: Expand to 10 levels

## Scope call, made explicit up front

The literal ask is "expand `level.csv` to 10 levels." As written today, that alone wouldn't do
anything a player could see: `GameScene.ts:28` hardcodes `const LEVEL_ID = '1'` with the
comment *"No level-select/progression system yet -- always load level 1's data."* Ten rows in
a CSV the game never reads past row 1 is dead content. This brief covers the CSV expansion
**and** the minimal progression logic to make it real — advancing through levels 1→10 across a
single run, rather than a level-select screen (out of scope, see below). Flagging this as a
scope decision rather than assuming silently, per the pattern the other briefs in this folder
use for open calls.

## Current state (confirmed by reading the code)

- `level.csv`: one row (`id=1`). Columns: `id,stage_name,duration,special_spawn,world_size,
  spawn_offset,augment_exp_min_drop,augment_exp_max_drop`.
- `level_enemies.csv`: `level_id,enemy_id,spawn_rate,enemy_level` — three rows, all
  `level_id=1`. `enemy_level` is a **separate namespace** from `level.csv`'s `id` — it's a
  foreign key into `enemy_scale.csv`'s own `level` column (an enemy's own difficulty tier),
  not the stage number. Both are called "level" in different files; don't conflate them when
  writing new rows.
- `enemy_scale.csv`: rusher/swarm/tank each have exactly one row, `level=1`. No harder tiers
  exist yet for any enemy.
- `GameScene.win()` (survive-timer expires) always calls `endRound(true)` → shows the
  "You Won" `GameEndPopup` with Restart/Main-Menu buttons. There is no "advance to next
  stage" path anywhere in the code today.
- `player_state.json` already has a `levelCompleted: 0` field — currently written nowhere,
  read nowhere. Looks like scaffolding for exactly this, never wired up.

Five tiers (not ten) — spawn tables below reuse tier 5 for the back half of the run rather

Checker's job to replace these placeholder numbers later, same caveat as everywhere else.

## Progression logic (`GameScene.ts`)

- Replace the hardcoded `const LEVEL_ID = '1'` module constant with an instance field,
  `private currentLevelId: string`, initialized from `player_state.json`'s new
  `levelCompleted` value (`String(playerState.levelCompleted + 1)`, clamped to `'1'` if that's
  `'0'` or below — i.e. resume from the next uncleared stage, start at 1 for a fresh save).
- `win()`: if `currentLevelId` is below `'10'`, don't call `endRound(true)`. Instead: persist
  `levelCompleted = currentLevelId` to `player_state.json` (reuse whatever write path
  `content/playerState.ts` already has, or add one if it's read-only today), increment
  `currentLevelId`, and restart the scene (`this.scene.restart()`) so `create()` re-runs
  against the new level's data — same mechanic the existing Restart button already uses, just
  triggered automatically instead of by a button. A brief "Stage Cleared" popup/flash before
  the restart is reasonable polish but not required for acceptance.
- `win()` at `currentLevelId === '10'`: same as today — full `endRound(true)`, "You Won"
  popup, run complete.
- `endRound(false)` (death) is unchanged — a loss doesn't advance or persist `levelCompleted`.

## Explicitly out of scope

- A level-select screen/menu. Progression here is strictly linear within one run — die and you
  restart from Stage 1 (or wherever `levelCompleted` last persisted, per above); there's no UI
  to jump to an arbitrary stage.
- GDD's boss-stage mechanic at stages 5/10 (`special_spawn` column stays blank). Real design
  work, not a data-expansion task.
- Enemy tiers 6-10 — stages 6-10 reuse tier 5 as their ceiling (see enemy_scale.csv above).
- Tuned numbers anywhere in this brief — every curve here is a placeholder, same as the rest
  of this project's content.

## Constraints

- Phaser 3 + TypeScript, no new libraries.
- Don't rename `level_enemies.csv`'s `enemy_level` column despite the naming collision with
  `level.csv`'s `id` — it's an existing FK other code already depends on; note the distinction
  in a comment if it isn't already, don't silently "fix" the name as part of this brief.

## Acceptance (QA)

- `tsc --noEmit` passes.
- Fresh save (`levelCompleted: 0`): surviving Stage 1's timer transitions into Stage 2 (world
  size, spawn rates, enemy tier all visibly change per the CSVs above) instead of ending the
  run.
- Reaching and surviving Stage 10 shows the existing "You Won" popup — run genuinely ends.
- Dying mid-run does not advance or persist `levelCompleted`.
- Restarting after a persisted `levelCompleted > 0` resumes from the next stage, not Stage 1
  (verify via `player_state.json`'s on-disk value, or `window.__qaGame`).

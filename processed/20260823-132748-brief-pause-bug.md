# Brief: Fix — bullets keep firing while the game is paused

Source: Assignment #9's adversarial QA agent (`submission/submission_9/adversarial_qa/`)
found this live, not from reading code — `report.json` entries 1-2, reproduced with
`bullets.length` growing 1→2 during a ~4s window with the Augment Choice popup open and no
input, then all bullets moving simultaneously the instant physics resumed.

## Root cause (confirmed by reading the code, not just the QA report)

`GameScene.openAugmentChoice()` / `resumeAfterAugmentChoice()` (`GameScene.ts:387,417`) pause
gameplay via a `paused` flag + `this.physics.pause()`. `physics.pause()` freezes every Arcade
body — existing bullets correctly stop moving on screen.

But `Player`'s auto-fire is a `scene.time.addEvent({ delay: fireIntervalMs, loop: true,
callback: () => this.fire() })` (`Player.ts`, constructor). Phaser's `scene.time` clock is
**independent of Arcade physics** — pausing physics does not pause it. `fire()` itself
(`Player.ts`) only early-returns on `this.dead || this.frozen` — it has no idea the scene is
paused, so it keeps spawning real `Bullet` instances on schedule throughout the popup. Those
bullets get physics bodies too, which `physics.pause()` immediately freezes at their spawn
position — invisible accumulation, not a visible glitch, until resume snaps them all into
motion at once.

`Player.move()` already has the right pattern (checks `dead`/`frozen`, no pause bug there —
movement is driven by physics velocity, which `physics.pause()` correctly freezes on its own).
This is specifically a **timer-vs-physics** gap, isolated to auto-fire.

## Fix

Give `Player` an explicit paused state, distinct from `frozen` (which is a permanent one-way
win-state flag with no unpause path — reusing it here would be semantically wrong and has no
way back):

- `Player.pause()` / `Player.resume()` — set/clear a new `private paused = false` field.
- `fire()`'s early-return becomes `if (this.dead || this.frozen || this.paused) return;`.
- `GameScene.openAugmentChoice()` calls `this.player.pause()` alongside its existing
  `this.physics.pause()`. `resumeAfterAugmentChoice()` calls `this.player.resume()` alongside
  `this.physics.resume()`.

That's the whole fix. No changes needed to `Bullet.ts`, `AoeLob.ts`, or the timer itself —
once no *new* bullets spawn during the pause window, there's nothing to accumulate and nothing
to burst on resume. Both `report.json` entries are two symptoms of the one root cause, not two
separate bugs.

## Explicitly out of scope

  (e.g. augment auto-fire timers armed by `activateGrenade()`-equivalents) — worth a follow-up

- Any change to `physics.pause()`/`physics.resume()` itself, or to `roundOver`'s separate

## Constraints

# Brief: Two new enemy archetypes — Ranged Shooter + Charger

All three current enemies (rusher/swarm/tank) share one behavior: `Enemy.chase()` walks
straight at the player and deals contact damage on overlap (`Enemy.ts`, `GameScene.ts`'s
player-enemy overlap). `enemy.csv`'s `type` column (melee/swarm) and `weapon` column are
parsed into `ResolvedEnemy` but **read nowhere** — purely descriptive today. This brief wires
both up for real, adding the project's first genuinely new enemy *behaviors* rather than a new
stat/reskin (which is why it's two enemies, not a same-shape addition like Tank was to
Rusher).

## Shared prerequisite: enemies need to damage the player without touching them

Today only `this.bullets` (player-fired) exists, and `GameScene`'s bullet-enemy overlap always
applies the scene-level `this.bulletDamage` (the player's currently-equipped weapon's damage)
— there's no path for a projectile to damage the *player*, and no path for a bullet to carry
its own damage value (only the player's weapon has one, scene-wide).

- `Bullet.ts`: add `damage: number` to `BulletConfig`, store it as a public readonly field on
  `Bullet`.
- `GameScene`: change the existing player-bullet/enemy overlap to read `(bulletObj as
  Bullet).damage` instead of the scene-level `this.bulletDamage` field (pass `damage:
  this.bulletDamage` when constructing the player's bullets in `Player.ts`'s `onFire`, so
  behavior is unchanged for the existing weapon). This removes the implicit "there's only ever
  one bullet damage value" assumption instead of working around it twice.
- `GameScene`: add `private enemyBullets: Bullet[] = []` (reset in `create()` alongside the
  other arrays) and a second overlap group: `physics.add.overlap(this.player,
  this.enemyBullets, (playerObj, bulletObj) => { (bulletObj as Bullet).destroy();
  this.player.takeDamage((bulletObj as Bullet).damage); })`.

## Data model

### `enemy.csv` — new columns, blank/0 default for existing rows (backward compatible)
```
id,name,desc,type,asset,weapon,scale,preferred_range,dash_burst_mult,dash_burst_ms,dash_cooldown_ms
rusher,Rusher,Walks straight at the player,melee,enemies/rusher,,0.16,0,0,0,0
swarm,Swarm,Flies in fast and erratic,swarm,enemies/swarm,,0.12,0,0,0,0
tank,Tank,Lumbering bruiser that shrugs off damage,melee,enemies/tank,,0.20,0,0,0,0
shooter,Shooter,Keeps its distance and fires,ranged,enemies/shooter,2,0.16,350,0,0,0
charger,Charger,Rushes in with sudden bursts of speed,melee,enemies/charger,,0.17,0,1.8,400,2200
```
- `preferred_range` (px): 0 = today's behavior (chase to contact, unchanged for all 3 existing
  enemies). Nonzero = new behavior (see Shooter below).
- `dash_burst_mult`/`dash_burst_ms`/`dash_cooldown_ms`: 0/0/0 = no dash (unchanged for
  everyone but Charger).
- `weapon` for `shooter` = `2`, a **new row in `weapon.csv`/`weapon_scale.csv`** (reusing the
  exact schema `getWeapon()` already parses — `type` column there is purely descriptive today,
  same as `enemy.csv`'s, so an enemy pointing at a weapon.csv row needs no schema change there,
  just a new id):
  ```
  # weapon.csv, append
  2,Shooter Bolt,The Shooter's ranged attack,enemy,enemies/shooter,900,0.08,0,30,0.01,10

  # weapon_scale.csv, append
  2,1,0,8,450,1.2
  ```

### `enemy_scale.csv` — new rows for both, level=1 only (matches existing single-tier rows;
if [brief-10-levels.md](brief-10-levels.md) lands first, extend both to its 5-tier pattern
instead of duplicating the curve-design decision here)
```
enemy_id,level,damage,health,speed
shooter,1,0,15,90
charger,1,18,25,140
```
`shooter.damage` is `0` — its damage comes entirely from its bullets (`weapon_scale.csv`'s
`damage`), not contact. Contact overlap still applies `(enemyObj as Enemy).damage`, so this
must be `0` or a Shooter standing still would also deal (unintended) contact damage.

## `Enemy.ts` changes

- Constructor gains `preferredRange`, `dashBurstMult`, `dashBurstMs`, `dashCooldownMs` on
  `EnemyStats` (all default-0 for the 3 existing spawn calls — no behavior change unless a
  CSV row sets them).
- `chase(targetX, targetY)`: if `preferredRange > 0` and `dist <= preferredRange`, stop (zero
  velocity, idle anim) **instead of** continuing to close in — this is what makes Shooter
  stand off rather than walk into contact. `dist > preferredRange` behaves exactly as today.
- New `startDashCycle()` (only called by `GameScene.spawnEnemy()` when `dashBurstMult > 0`):
  a repeating `scene.time.addEvent` at `dashCooldownMs` that, on fire, tints the sprite
  (reuse the existing hit-flash tint call, different color, so the burst is telegraphed) and
  multiplies `this.speed` by `dashBurstMult` for `dashBurstMs`, then reverts. `chase()`'s
  existing velocity-from-`this.speed` logic needs no other change — the multiplier just makes
  the same math produce a faster velocity for that window.

## `GameScene.ts` changes

- `spawnEnemy()`: read the new `enemy.csv` columns via `getEnemy()` (already returns the full
  `ResolvedEnemy`, just add the new fields to the interface in `content/enemies.ts` the same
  way `weapon`/`type` are already passed through unused), pass them into the `Enemy`
  constructor, call `startDashCycle()` if applicable.
- New `fireEnemyWeapon(enemy: Enemy)`: for any spawned enemy with a non-blank `weapon` FK,
  arm a `scene.time.addEvent` at the resolved `weapon.fireRate`-derived interval (same
  `1000 / fireRate` math `Player.ts` already uses) that spawns a `Bullet` aimed from the
  enemy's position at the player's current position, pushed into `this.enemyBullets` (mirror
  of `Player.fire()`/`trackBullet()`, enemy-owned instead of player-owned). Stop firing once
  the enemy is `dying` — same guard `Enemy.chase()` already uses.
- `archetypes.ts`: add `shooter`/`charger` entries. **Update since this brief was written:
  real art now exists at `public/assets/enemies/ranged/*.png`** (same frame-count convention
  as rusher — `idle_0..5`, `walk_0..7`, `death_0..9`, plus fall/hit/jumpEnd/jumpStart/roll,
  all unused today) — Shooter should load its own real frames from there
  (`shooter_*` keys → `assets/enemies/ranged/*.png`), not a Rusher placeholder. Charger still
  has no art of its own — keep the placeholder-reuse pattern for Charger only (`charger_*`
  keys → `assets/enemies/rusher/*.png`), swappable later with no code change once Charger art
  exists, same documented pattern Tank originally used.
- **Also update, same pass:** `public/assets/enemies/tank/*.png` real art now exists too
  (same frame-count convention), but `characterAssets.ts` still points every `tank_*` texture
  key at `assets/enemies/rusher/*.png` — that was the deliberate placeholder before any tank
  art existed (see the file's own comment). Swap Tank's load paths from
  `assets/enemies/rusher/${anim}_${i}.png` to `assets/enemies/tank/${anim}_${i}.png` (same
  `tank_` key names, same `ANIMS`/`TANK_DEATH_FRAMES` counts — just the source path changes).
  Small, separate from the Shooter/Charger work above, but bundled into this same pass since
  both art drops landed together.
- `level_enemies.csv`: not required for acceptance, but add `1,shooter,5000,1` and
  `1,charger,5500,1` so the new archetypes are actually reachable in Stage 1 for QA, rather
  than only existing in code with nothing spawning them.

## Explicitly out of scope

- Real Charger sprite art — no art exists for it yet, placeholder-reuse pattern only (Shooter
  and Tank both get their real art in this pass; Charger doesn't have any to use).
- Enemy bullets colliding with player bullets, or any friendly-fire between enemies.
- Tuned numbers (damage/range/burst timing above are placeholders, same caveat as always).
- Wiring these into more than Stage 1's spawn table — that's `brief-10-levels.md`'s job if it
  lands, not duplicated here.

## Constraints

- Phaser 3 + TypeScript, no new libraries.
- Reuse `Bullet.ts` for enemy projectiles — no new projectile class.
